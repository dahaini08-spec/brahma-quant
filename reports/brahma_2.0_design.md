## 0. 一句话

> **砍掉所有不被证据支撑的复杂度，让一个25K行的精瘦系统自己证明自己能赚钱——证明不了的维度进冷冻室，证明了的才加权。**

## 1. 设计哲学（自上而下）

### 1.1 审计之问的回答

外部审计的核心指控：12.7万行代码构建了35维打分+10状态机+6-Agent Council+9层熔断，
而唯一有统计意义的胜率是34.4%（n=96，低于抛硬币）。
**工程投入顺序颠倒** = 给未证明有效的系统打补丁积累的债务利息。

梵天2.0 的答案不是「再修一层」，而是**倒转投入顺序**：

```
1.0 思路: 复杂度先行 → 期望值待验证（现状）
2.0 思路: 期望值先行 → 复杂度是期望值的函数（每+1K行代码必须对应≥+0.05% EV/笔的验证提升）
```

### 1.2 五条宪法（2.0新增）

1. **期望值是唯一北极星**：纸面账本EV/笔（30日滚动，n≥30才有效）。分析次数/维度数/代码行数=虚荣指标，禁止作为汇报KPI。
2. **证据分层**：实盘证据 > 纸面证据 > 回测证据 > 直觉。当前实盘n=1（TRUMP -1.47U），纸面盘是唯一在积累的证据源。**两口径永不混用**（1.0已封印此条，2.0延续）。
3. **最小复杂度**：2.0核心总预算≤25K行。新功能必须置换等量旧代码（负熵预算，只许替换不许叠加）。
4. **Fail-loud**：关键路径（打分/风控/执行/结算）禁止静默吞异常。非关键路径允许降级但必须留痕（结构化日志+计数器）。
5. **每个cron必须声明消费者**：没有明确「谁读它的输出」的定时任务直接砍。

### 1.3 40年交易员视角：什么真正赚钱

合约市场的钱来自四件事，且只有这四件：
- **方向**（体制判断）——80%的盈亏由方向决定，这有回测大样本支撑（体制→策略映射表）
- **位置**（FVG/OB/清算地图共振区）——在哪进，而不是什么时候进
- **风险**（SL=结构失效位+ATR验证；仓位=体制乘数×基础仓位）——活下来才有复利
- **不对称**（RR≥1.5）——让单笔亏损成本可控，让正确时的盈利覆盖成本

2.0的信号层只服务这四件事。其余维度（94维中的82个）对这四件事没有已证明的贡献——它们去冷冻室。

## 2. 架构（自上而下）：4层管道 + 1个证据中枢

```
┌─────────────────────────────────────────────────────┐
│  L0 证据中枢 Evidence Hub                             │
│  paper_ledger(SSOT) + 每日结算 + IC周审 + 桶效力审计     │
│  唯一写入者: 结算器。所有层只读它的反馈。                  │
└────────────────────▲────────────────────────────────┘
                     │ 结算反馈（唯一回流方向）
┌────────────────────┴────────────────────────────────┐
│  L3 执行层 Executor                                  │
│  唯一执行入口；双硬闸(--allow-live + BRAHMA_ALLOW_LIVE) │
│  纸面模式为默认；实盘需苏摩111单独解锁                   │
├─────────────────────────────────────────────────────┤
│  L2 风控层 RiskGate (fail-closed)                    │
│  5条硬规则，任一不过=拒绝+留痕:                          │
│   R1 SL距离≥1.5×ATR1H(100X另验)                       │
│   R2 仓位≤体制乘数×基础仓位(≤10% NAV)                  │
│   R3 体制禁令(如BEAR_RECOVERY禁空)                     │
│   R4 重复建仓阻断(同symbol同方向未平仓)                  │
│   R5 日亏≥3% NAV停机24h                                │
├─────────────────────────────────────────────────────┤
│  L1 信号层 Signal（纯函数）                            │
│  输入: 行情dict(由L0录制/提供) 输出: 信号dict             │
│  零网络调用、零全局可变状态 → 可离线回放CI               │
│  12个已证明维度 + 体制门控 + 方仓标的专属匹配            │
├─────────────────────────────────────────────────────┤
│  L0 数据层 MarketData（唯一网络出口）                   │
│  连接池(Session keep-alive) + 磁盘缓存 + 离线拦截        │
│  录制模式: 每次实时请求同步落盘 → 供L1回放测试            │
└─────────────────────────────────────────────────────┘
```

**单向依赖铁律**：L3→L2→L1→L0。禁止反向import。CI用import-linter强制。

**纯函数化信号层**直接根治审计「打分引擎直连API、没法离线测试」的问题：
L0录制真实行情序列 → L1吃序列出信号 → 信号快照进版本库 → 任何维度改动跑回放，
输出变了=显式diff审查。**API抖动永远炸不到调用栈深处**——它最多让L0返回STALE_DATA。

## 4. 证据驱动迭代循环（2.0的心脏）

### 4.1 IC周审（每周一 09:00 UTC）

```
上周每笔纸面交易 → 快照当时的维度值 → 每维度IC = corr(dim, pnl)
  IC > +0.02  → 保留，权重可+10%
  IC ∈ 混合区 → 观察，不加权不减权
  IC < -0.02  → 权重×0.8；连续4周负 → 进冷冻室
  冷冻室复活   → 需连续2周IC>+0.02 + 苏摩111批准
```

### 4.2 桶效力月审（每月1日）

```
每桶 = 体制×方向（如BULL_TREND:LONG）
  n < 30          → 该桶禁实盘（纸面继续积累）
  WR < 50% 且EV<0 → 纸面继续，禁实盘
  WR ≥ 55% 且EV>0.3%/笔 → 申请苏摩111解锁该桶实盘
```

**这就是2.0对「34.4%低于抛硬币」的正面回答**：不再靠印象判断哪个桶能打，
桶的生死由纸面数据+效力门槛决定，AI/苏摩都不再拥有「我觉得」的空间。

### 4.3 可证伪的中心命题（写死在设计书里）

> **命题**：BTC/ETH永续，体制允许方向 + FVG/OB共振区挂单 + SL结构失效位 + RR≥1.5，
> 在taker4bp+滑点3bp+funding1bp/8h真实成本下，纸面EV/笔 > 0，且30笔桶样本WR≥52%。
> **证伪条件**：任意桶30笔后EV≤0 → 该桶进冷冻室，触发器自动执行，不讨论。

## 5. 宪法补充条款（Fail-loud / Schema / 预算）

### 5.1 关键路径异常规范

```python
CRITICAL_PATHS = ('signal_scoring', 'risk_gate', 'order_execution', 'settlement')

# 规则:
# 1. 关键路径的except必须: error_ledger.count(path) + log(结构化) + P1推送（首次）
# 2. 全库70处裸except → 清零
# 3. except Exception 必须带 as e，e写入结构化日志（module/phase/symbol/trace_id）
# 4. 数据缺失 → 返回 {'status': 'STALE_DATA', 'dims_missed': [...]}，禁止返回缺键dict
# 5. error_ledger计数 > 5次/天 → 自动P0（说明系统性问题，不是偶发）
```

### 5.2 Schema即代码

- `init_db.sql`：signals、ledger、ic_history、error_ledger四张表，进git，部署脚本只跑它
- 任何schema变更走migration文件（V001_、V002_...），禁止手改生产库

### 5.3 负熵预算（复杂度只能置换不能增加）

- 每个PR声明行数变化；净增>500行 → 需要苏摩111特批
- 冷冻室模块的代码在冻结期不计入维护成本（不修bug不加功能）
- `_deprecated/`、`_empty_trash/` → git rm（历史即归档，目录即债务）
