## 🔧 全局方案（5层一体）

### Layer 1: 评分器层（已完成基础）

**设计原则：只用盲测IC>0的维度，权重按IC排序**

| 维度 | IC | 权重 | 评分范围 |
|------|-----|------|---------|
| regime_direction | +0.0146 | 40% | +30/-20（体制×方向bonus） |
| rsi_extreme | +0.0143 | 30% | +15/-15 |
| bb_squeeze | +0.0137 | 20% | +12/-8 |
| resonance | +0.0024 | 10% | +10/-3（弱正，保留但不强制） |

**已验证：** IC从-0.0027→+0.0150，5.6x提升 ✅

**待优化：**
- [ ] P1-1: 权重微调（用grid search找最优权重比）
- [ ] P1-2: min_score阈值搜索（90/95/100/105/110，找WR拐点）

### Layer 2: 入场过滤层

**设计原则：只做最强alpha组合，弱组合直接过滤**

**2a. 体制×方向白名单**
| 体制 | 方向 | 历史WR | 决策 |
|------|------|--------|------|
| BULL_TREND | LONG | 70.5% | ✅ 保留（S级alpha） |
| BEAR_TREND | SHORT | 72% | ✅ 保留（S级alpha） |
| BULL_EARLY | LONG | 64.4% | ✅ 保留（A级alpha） |
| BEAR_RECOVERY | LONG | 72.5% | ⚠️ 仅score≥155 |
| CHOP_MID | SHORT | 57.3% | ⚠️ 仅score≥110，仓位减半 |
| 其他 | * | <52% | ❌ 过滤 |

**待验证：**
- [ ] P2-1: 只保留BULL_TREND:LONG + BEAR_TREND:SHORT，跑回测看WR/IC/EV
- [ ] P2-2: 加入BULL_EARLY:LONG + BEAR_RECOVERY:LONG，跑回测看边际改善
- [ ] P2-3: 确定最优白名单组合

**2b. min_score动态阈值**
```
当前：固定90（15m）/ 95（1h）
提议：
  - BULL_TREND/BEAR_TREND: 90（强体制降低门槛）
  - BULL_EARLY/BEAR_RECOVERY: 100（弱体制提高门槛）
  - CHOP_MID: 110（最弱体制最高门槛）
```

**待验证：**
- [ ] P2-4: 对比固定阈值vs动态阈值的WR/EV差异

### Layer 3: 出场层

**设计原则：让利润奔跑，不保护浮盈，时间止损兜底**

**3a. RR自适应（核心创新）**
```
当前问题：RR固定1.5 → TP=3% 太远，触达率低
提议：RR按体制调整
  - BULL_TREND:LONG → RR=2.0（趋势中让利润奔跑）
  - BEAR_TREND:SHORT → RR=1.8（趋势中但空头回补更快）
  - BULL_EARLY:LONG → RR=1.5（不确定期保守）
  - BEAR_RECOVERY:LONG → RR=1.5（保守）
  - CHOP_MID:SHORT → RR=1.2（震荡快进快出）
```

**待验证：**
- [ ] P3-1: 跑5个RR配置（1.2/1.5/1.8/2.0/2.5），找每个体制×方向的最优RR
- [ ] P3-2: 对比固定RR=1.5 vs 自适应RR的net EV

**3b. 浮盈保护 redesign**
```
当前问题：2.5×ATR浮盈保护 → 35%信号被保本扫出 → WR虚高
提议：不用浮盈保护，改用"移动止损"（trailing SL）
  - 浮盈 > 2×ATR → SL移到入场价（保本）
  - 浮盈 > 4×ATR → SL移到入场+1×ATR（锁定利润）
  - 浮盈 > 6×ATR → SL移到入场+3×ATR（让利润奔跑）
```

**待验证：**
- [ ] P3-3: 对比无浮盈 vs 2.5×ATR保本 vs trailing SL的WR/EV
- [ ] P3-4: 如果trailing SL有效，找最优ATR倍数

**3c. 时间止损**
```
当前：15m=48根(12h), 1h=24根(24h)
提议：
  - 趋势体制（BULL/BEAR_TREND）：延长到36根（36h），给趋势时间
  - 震荡体制（CHOP）：缩短到12根（12h），快进快出
```

**待验证：**
- [ ] P3-5: 对比固定hold vs 体制自适应hold的WR/EV

### Layer 4: 仓位管理层

**设计原则：强信号重仓，弱信号轻仓，风险预算制**

```
当前：固定5% NAV × 5x杠杆 = 25% notional
提议：按score分档
  - score ≥ 130: 5% NAV × 5x = 25% notional（强信号满仓）
  - score 110-129: 3% NAV × 5x = 15% notional（中信号半仓）
  - score 90-109: 2% NAV × 5x = 10% notional（弱信号轻仓）
  - score < 90: 不入场
  
  体制折扣：
  - BULL_TREND/BEAR_TREND: ×1.0（无折扣）
  - BULL_EARLY/BEAR_RECOVERY: ×0.7
  - CHOP_MID: ×0.5
```

**待验证：**
- [ ] P4-1: 对比固定仓位 vs 分档仓位的PnL/Sharpe/最大回撤
- [ ] P4-2: Kelly公式最优仓位 vs 当前分档方案

### Layer 5: 跨标的扩展层

**设计原则：先用BTC/ETH验证，再扩展到山寨**

```
当前问题：山寨币无regime标签 → 0/5跨标的通过
根因：regime检测需要4H K线+日线+周线三周期对齐，山寨历史数据不完整
解决方案：
  Step 1: 用BTC regime作为代理regime跑山寨（BTC涨→SOL大概率涨）
  Step 2: 验证代理regime的WR是否≥52%
  Step 3: 如果代理有效，扩展到10个山寨
  Step 4: 逐步积累山寨自己的regime标签
```

**待验证：**
- [ ] P5-1: 用BTC regime跑SOL/BNB/ADA，看WR是否≥52%
- [ ] P5-2: 如果有效，扩展到XRP/DOGE/LINK/LTC/DOT
- [ ] P5-3: 对比BTC代理regime vs 山寨自有regime（有数据的标的）

## 🚨 设计原则（三方共识）

1. **不再打补丁** — 每个变量改动都要跑完整回测
2. **盲测优先** — 任何改动都用IC/WR/WF数字验证，不凭直觉
3. **最小改动** — 一次只改一个变量，隔离效果
4. **先减后加** — 先砍到最小可用集，再逐步加维度验证
5. **成本意识** — net EV = gross EV - 0.13%，永远扣成本算
